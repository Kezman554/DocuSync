2026-10-19 — Redaction (removes content, not covers it)
- Model: annotation { type: 'redaction', rect } in source PDF space; drawn,
  moved, resized (free) and deleted on the existing layer. "▨ Redact" tool
  stays armed for several boxes; a bare click makes nothing. Hatched box
  with red outline in the viewer; "Redacted" badge on sidebar thumbnails.
- Export (exportPdf.buildPdf `flatten` option): redacted pages are copied
  into a throwaway staging PDF, given DocuSync's annotations, watermark and
  page number as usual, rendered UNROTATED by pdf.js at 150 dpi
  (AnnotationMode.ENABLE, so source annotations/form appearances become
  pixels too), boxes painted black snapped OUTWARD to whole pixels (no
  half-covered anti-aliased edge), then encoded as PNG and JPEG q.85 and the
  smaller kept. Output page = fresh page at the visible (crop) size with the
  edited rotation and one image. Staging is never copied into the output.
- Enforcement choice: everything on a redacted page, including DocuSync's
  own text, is baked into the image rather than drawn as vectors on top.
  One rule ("a redacted page is exactly one image") is checkable; deciding
  which vector text clears a box would need exact glyph bounds for rotated
  text and watermarks, and a near-miss leaks.
- Fails closed: no flattener, a throwing one or a short result → ExportError,
  nothing downloaded.
- Metadata: if any page is redacted, the source's Info (title, author,
  subject, keywords, creator) is not copied; only Producer is set.
- Warning: Export PDF asks first; Extract pages and Compress show it inline
  when their pages include redacted ones. Image export needs none.
- CLAUDE.md Conventions now records the flattening exception.

  flattened page; 10 pt text clearly readable.
